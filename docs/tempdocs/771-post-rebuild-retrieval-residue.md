# 771 — post-rebuild retrieval residue

## §A. The three items (evidence banked; do not re-derive)

1. **Two-hop join-key affordance** (from 769 §E / F-039 diagnosis; dominant).
   The answer doc in bridge-schema questions is reachable ONLY via the bridge
   entity's name — the M3 oracle put both golds at rank 1–2 (hybrid AND
   lexical) for every qid once the name was queried, while single-shot
   structure-phrased retrieval structurally cannot produce it (answer doc
   absent from all legs' top-100 in 12/17 B2 cells). Winning agents already
   perform the two-step chain; failing ones stop after hop-1. 770 §E.4
   withdrew the `fetch`-shaped lever on measurement, and its register
   correction sharpened WHAT the item actually is: since `hit.id` IS the
   filesystem path, tool shape is not the gap — the question is whether the
   *delivered evidence content carries the bridge entity's name* so the agent
   can re-query (an excerpt/evidence-content question), plus whether the
   surface should cue the continuation. 770's §A.2 measurement points the
   same direction: 50.3% of post-search Reads (N=862) targeted docs search
   never returned — retrieval coverage, not ergonomics, dominates the
   agent-side failure. D-005 bounds any mechanism: react to the query's own
   results, never a per-corpus router; and 770 §A.4 downgraded F-016
   (schema-bloat) to a weak prior — schema additions are arguable on merit.
2. **Hybrid fusion-burial of leg-visible gold** (from 769 §E M2; bounded,
   engine-owned). In 3/17 cells a single leg had gold ≤20 (q3: vector held
   BOTH golds ≤10) while production hybrid buried them to 23–24; 10 more
   cells had the bridge doc at rank 21–100 in a semantic leg. This is a
   D-005 "fusion is a ranking step, not a recall gate" leak instance —
   the same class F-025's recall-complete pool addressed at the CE window,
   here at the agent-visible k. Candidate instruments exist (staged-recall
   decomposition, leak-gate); no new machinery is licensed before the §C
   re-measurement sizes the class on rebuilt strata.
3. **Post-search read-amplification** (from 765 §E / 770 §H "§A.2 — routed
   to engine/relevance lane"). Agents re-Read full files after search
   (44.7% of post-search Reads target a returned path; 157 full-file Reads
   at legal-10k), because the delivered snippet doesn't carry the
   answer-bearing span. 770 measured and reshaped what the surface DELIVERS;
   whether the engine should select/return better spans (excerpt/passage
   quality at the retrieval layer) is this item. Couples to the RAG passage
   machinery (F-038's union leg, chunk evidence) — conform, don't fork.
