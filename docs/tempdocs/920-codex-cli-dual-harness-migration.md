# 920 — Codex CLI dual-harness migration

## Goal

Make Codex CLI, the ChatGPT desktop app, and the Codex IDE extension safe and
productive in JustSearch without breaking the existing Claude Code workflow.
The migration preserves project policy as shared authority while using
harness-specific adapters for discovery, tools, hooks, transcripts, and models.

## Acceptance contract

- [x] `AGENTS.md` carries the cross-harness invariants and startup workflow.
- [x] Every checked-in Claude project skill has a deterministic Codex projection
      under `.agents/skills`, including explicit-only invocation policy.
- [x] Project Codex config exposes `justsearch-dev` without a committed secret.
- [x] Codex hooks are generated from `governance/agent-hooks.v1.json` and adapt
      Codex event/tool shapes before invoking shared policy hooks.
- [x] Claude-only events and transcript assumptions are either translated or
      explicitly excluded with a tested reason.
- [x] Hook integrity, prompt-surface inventory, instruction budgets, and docs
      govern both harnesses.
- [x] Codex-native subagent roles preserve the repository's delegation intent
      without Claude model names.
- [x] Codex OTel wiring and Codex-only sink startup are documented and exercised.
- [x] A clean Codex non-interactive smoke proves instruction, skill, MCP, and hook
      discovery; deterministic unit/contract tests prove blocking behavior.
- [x] Relevant repository checks and the minimum Gradle compile gate are green.

## Implementation notes

The existing Claude hook scripts remain the behavioral implementation where
their policy is harness-neutral. A Codex adapter normalizes event payloads,
serializes matching handlers to avoid order races, and combines their decisions.
Hooks that fundamentally depend on Claude-only transcript or lifecycle semantics
must gain a Codex reader or be excluded explicitly; silent no-op parity is not
acceptable.

## Outcome and evidence

- `AGENTS.md` is the cross-harness authority. The six Claude hard invariants are
  generated by `agent-instructions-sync.mjs` rather than maintained twice.
- `skills-sync.mjs` projects 27 Claude skills to 31 committed Codex files; four
  explicit-only skills receive `agents/openai.yaml` policy.
- `.codex/config.toml` registers the required `justsearch-dev` server and resolves
  the active Git root, so both repository-root and module-subdirectory launches
  work. No credential is committed.
- `.codex/hooks.json` is generated from the shared manifest. The adapter maps
  Codex patch/shell/agent shapes, preserves blocking decisions and input rewrites,
  understands Codex rollout edits/context, and explicitly excludes three
  Claude-only semantics.
- The installed Codex CLI, authenticated with ChatGPT, loaded `AGENTS.md`,
  selected the generated `dev-stack` skill, and called
  `justsearch.dev.quick_health` from both the worktree root and `modules/ui`.
- Current Codex OTel uses separate logs/traces/metrics exporters and histogram
  token points. A fresh temporary sink received all three streams and produced
  normalized `gen_ai.usage` records; decoder coverage now includes
  `cache_write_input`.
- Green evidence so far: Codex parity, MCP live projection, MCP surface honesty,
  agent analytics, governance tests, hook integrity, OTel sink, Markdown,
  canonical links, workflow triggers, instruction budget, root README,
  skill/doc generators, and `git diff --check`.
- After rebasing the publish candidate onto current public `main` and
  regenerating the Codex skill projections, `gradlew build -x test` and
  `gradlew test` completed successfully with Temurin JDK 25. Frontend
  `typecheck` and the complete frontend unit suite also passed.
