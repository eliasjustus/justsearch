## 2. Findings

- **F1 (HIGH, BLOCKING — Install AI reliability + honest terminal state).** In-sandbox:
  BITS failed 100% (service Stopped/Manual; 17 fallbacks), the curl fallback failed 14×
  (13× exit 52, 1× exit 35), 5 of 7 packages failed on first run, three Repair passes
  recovered 6 of 7, and `splade` stayed permanently wedged on ONE 872-byte `config.json`
  that fetches by hand in 0.41 s (HTTP 200, SHA matches manifest). The resume-record
  hypothesis was REFUTED by the product's own log ("Resume decision for
  config.json.partial: FRESH (no partial bytes on disk)") — the wedged-file root cause is
  OPEN. Sharpest fact: functional impact was NIL (the SPLADE model was on disk and loaded
  — 1,660 real ORT calls; all four enrichment signals reached 100%) while the product
  permanently reports `installedFully:false` / "A required component is missing — use
  Repair", an endless repair loop that can never succeed. Contains the known INS-005
  class (abort-remaining-after-first-failure) plus an honesty defect the class doc
  doesn't cover: completion bookkeeping diverges from functional reality.
  **Routing: wave worker C — root-cause investigation + design first, implementation
  after review (823 §5). Regression home: unit/live-stack tests on AIInstallService
  failure isolation + terminal-state truthfulness; round-17 charter re-verifies by
  TRIGGERING a failure, not observing a clean install.**
- **F2 (MEDIUM — publisher identity mismatch).** Windows Apps list / uninstall registry
  entry shows Publisher=`justsearch` (lowercase bundle string), not the signing identity
  "Elias Justus". The user-visible publisher must match the certificate CN.
  **Routing: wave worker A (bundle publisher metadata).**
- **F3 (MEDIUM — unsigned uninstaller).** The ONE unsigned shipped PE of 173 is
  `uninstall.exe`, generated by NSIS on the user's machine at install time — it cannot
  inherit the bundle signature, and the uninstall path is exactly where trust matters.
  Found by an off-charter full-sweep (a one-PE spot-check would have missed it).
  **Routing: wave worker A (uninstaller signing at build time — NSIS uninstfinalize /
  Tauri signCommand path; verify on the next signed CI build).**
- **F4 (MEDIUM — repair API opacity).** `POST /api/ai/install/repair` returns HTTP 400
  with a COMPLETELY EMPTY body; the endpoint's body shape is absent from
  `docs/reference/api-contract-map.md`. A caller cannot learn the required shape.
  **Routing: folded into worker C's F1 design (same service).**
- **F5 (LOW — Health card transient staleness).** Immediately after ingest drained, the
  card header read "INDEXING - 0 RUNNING - 0 QUEUED" while the body still listed queued
  rows ("+2649 MORE") at a moment every API authority read idle; self-corrected in ~2–4
  min; safe (pessimistic) direction. **Routing: log-only this wave; candidate for the
  post-0.2.0 progress-surface backlog.**

## 3. Golden parity: BLOCKING exit explained as an instrument artifact (verify, then fix the instrument)

`check_golden_parity.py` exited 1: q04/q06/q08 lost golden #1 from captured top-3 (and
7/10 queries sat below the descriptive overlap floor). The round's own EP record explains
it: at capture time `/api/ai/runtime/status.onnxFeatures.embed` read
`executionProvider=cpu, gpuFallback=true, fallbackReason="GPU session not yet initialized
(lazy)"` — query vectors were CPU-FP32 against a GPU-FP16 baseline. Diagnostic signature
(from the report's per-leg attribution): SPLADE 8–10/10 and text mostly high while the
dense leg alone collapses (0–5/10) with shared-pair score deltas ~0.06–0.20 — six orders
of magnitude above the calibrated sandbox↔sandbox dense envelope (1.8e-4). Top hits are
all scifact (the tempdocs corpus did NOT displace results), so corpus composition is not
the cause. **Not adjudicated as a product ranking regression.** Two consequences:
1. **Harness fix (wave worker B): gate golden capture on `embed.executionProvider ==
   "cuda"`** (the observed-EP fields shipped for exactly this) — wait/retry until warm,
   and record the EP state alongside the capture so finalize can see it.
2. Honest residual: the pre-existing dev↔sandbox systematic (734 finding 5) remains open
   and is NOT settled by this explanation; round 17's capture under a warm GPU session is
   the discriminating measurement.
